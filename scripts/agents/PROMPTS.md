# 翻译代理提示词（可复用）

三个阶段的提示词模板。实测结论见 README「翻译架构」：**阶段 0 + 阶段 1 是主力，
阶段 2（审校）默认不开，只对确定性质检不达标的单元按需触发。**

---

## 阶段 0 · 卷级上下文包 `build-context`

每个卷跑一次，产出该卷唯一的术语与风格权威，写 `data/_jobs/context-<vol>.json`
与可合并的 `data/_jobs/ctx-<vol>.glossar.csv`。

要点：
- 先自行 `node scripts/dump.mjs --vol <vol> --chunk N --from A --to B` 抽样若干章节看原文，
  并读现有 `glossary/hegel_glossar.csv`。
- 输出 `styleGuide`（5–8 条可直接执行的中文风格规则）、`entries`（40–120 条术语/人名/书名，
  只收真正的术语，宁缺勿滥）、`forbidden`（禁止译法对）、`doNotTranslate`。
- 风格规则要具体到可执行，例如：
  - 把 Hegel 的长句保留为一整句，用逗号/破折号/分号按原文层级展开，不拆成流水短句；
  - 用白话，不用论文腔（不写"所谓……者，乃……也""兹、盖、故尔"）；
  - 一个德文词只给一个中文词，全卷统一；术语用通行译名（扬弃、自在自为、定在、环节、表象）；
  - 希腊语/拉丁语/文献出处/缩写保留原文，必要时括注中文；
  - 句数严格对齐：德文一句对中文一句，不合并、不拆分。

## 阶段 1 · 单元翻译 `translate-unit`

输入 `data/_jobs/<unit>.in.json`，输出其 `outFile`。

- 必读 `context-<vol>.json` 并服从：术语照 entries，禁译照 forbidden。
- 两步走：先德→英逐句（一句对一句，保留长句结构），再英→中逐句（白话、贴原文语气）。
- 每个 block：`k="h"` 输出字符串 en/zh；`k="p"` 输出与 `sents` **等长同序**的数组。
- 不许增补原文没有的内容；德语残句照残句译。
- 输出 UTF-8 JSON（无 BOM），形如
  `{ "unit": "...", "stage": "draft", "blocks": { "9": { "h": "...", "en": [...], "zh": [...] } } }`

## 阶段 2 · 保守审校 `review-unit`（按需）

只对确定性质检报错的单元运行，提示词基调照搬 BookLLM 的保守 QA 设计：

- 这是 **QA 校正**，不是重译、不是风格改写。
- 只修明确缺陷：误译（主宾/指代/否定/情态/时序/因果）、漏译、增译、残留德语、
  术语违规（词表未落实或用了禁止译法）、影响理解的机器腔。
- **没有明确缺陷就原样保留**；只做最小改动；**不许改得更文学、更优雅、更学术**，
  不许抹平 Hegel 本人的粗粝，不许加解释。
- 原地重写同一文件（同结构、同块集、同数组长度），`stage` 改为 `"reviewed"`，
  并报告改动句数与缺陷分类计数。

---

## 批处理与限额

- 子代理并发上限为 8，故 workflow 里每批 6 个单元（`parallel` + 分组）。
- 单元自包含：输入文件内含德语原句、块哈希、输出路径，代理之间无共享状态。
- 术语：代理**不直接改共享词表**，只写自己的 `data/_jobs/<unit>.glossar.csv`，
  由 `merge-glossar.mjs` 统一合并（已有条目保留、新条目追加、可疑项列出示警）。
